# Evidência do MVP técnico — 20/10/2026

Fluxo verificado: painel React → API Django/DRF → PostgreSQL → API pública → site Next.js. O site e o painel usaram requisições reais; não houve interceptação de APIs pelo Playwright.

## Ambiente observado

Windows, Python 3.12, PostgreSQL 18.4, Node.js 24, Django 5.2, React 19, Next.js 16 e Microsoft Edge headless. O PostgreSQL local usa dados persistentes fora do repositório. A API executou como `tavvo_app`, sem superuser, propriedade de tabelas ou `BYPASSRLS`; migrações e criação do banco de testes usaram conexão owner separada.

O armazenamento local foi o servidor Moto, um emulador do protocolo S3. O upload percorreu navegador, API, emulador e PostgreSQL; os bytes foram servidos pela rota pública. Esse teste não é evidência de execução do MinIO do Compose nem de S3 produtivo.

O seed criou A com três categorias e cinco produtos e B com duas categorias e três produtos, com gestores distintos. Os testes acrescentaram registros identificados como E2E. Restaurante, categorias, produtos, mesas, configurações e os dois cardápios permaneceram iguais após reiniciar o banco e as aplicações. A verificação também confirmou novamente os privilégios restritos da conexão runtime.

Problemas encontrados e corrigidos durante os testes: rótulos de seleção/ajuda que prejudicavam a identificação acessível dos campos; contrato de QR/configurações pouco específico; ator da auditoria com nome de campo divergente; controles de edição de catálogo mostrados para administrador sem associação; colisão de enums no OpenAPI. A suíte final usa o código corrigido.

## Reprodução

Siga [execução local](../runbooks/local-development.md), depois [testes de navegador](../../tests/e2e/README.md). `scripts/verify_persistence.py` salva e compara os dados completos em `.local/`, ignorado pelo Git. Senhas, cookies, segredos MFA e códigos de recuperação não fazem parte das evidências versionadas.

## Limites e pendências

- Docker não está instalado nesta estação. Build e startup completo do Compose, MinIO e Mailpit aguardam o resultado do job `browser` no GitHub Actions; YAML e Dockerfiles preparados não equivalem a execução comprovada.
- O envio de recuperação tem testes automatizados de fila/token/worker, mas SMTP externo e entrega em caixas reais não foram validados.
- Backups e restauração têm runbook; não houve ensaio de restauração. Reiniciar com dados preservados não equivale a restaurar backup.
- Domínios usam associação e verificação manual; DNS, certificados, provedor brasileiro, capacidade e retenção dependem de definições operacionais.
- Nenhum deploy produtivo, contratação ou funcionalidade de pedidos/pagamentos foi realizado.

Os critérios funcionais locais foram exercitados. O critério de execução completa do Compose permanece pendente até evidência de CI ou de outra máquina com Docker.
